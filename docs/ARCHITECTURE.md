# Архитектура MailVault

Локальный контур на Windows-ПК пользователя. Outlook остаётся единственным «окном» к почтовому серверу (если сервер вообще нужен). ИИ-контур к серверу и в интернет не подключается.

## 1. Граница доверия

```
                    корпоративная сеть / Exchange / M365
                                  │
                                  │  только процесс Outlook.exe
                                  ▼
┌──────────────────────────────────────────────────────────────────────────┐
│  ПК пользователя                                                         │
│                                                                          │
│  Outlook Classic (Cached Exchange → OST/PST)                             │
│       │ NewMailEx / папка Inbox                                          │
│       ▼                                                                  │
│  VSTO / COM Task Pane  ──named pipe──►  Orchestrator (localhost)         │
│       │                                      │                           │
│       │ Extended MAPI sidecar                ├─ Classifier (8B)          │
│       │ (отдельный процесс, не OOM)          ├─ Embedder (BGE-M3)        │
│       ▼                                      ├─ Drafter (27B/32B)        │
│  SQLite WAL + FTS5 + sqlite-vec              └─ Draft writer → Outlook   │
│                                                                          │
│  WFP: llama-server, orchestrator, embedder → BLOCK outbound ≠ loopback   │
└──────────────────────────────────────────────────────────────────────────┘
```

**Правило:** письмо может покинуть машину только если человек нажал «Отправить» в Outlook. Черновик, который написала модель, — локальный объект MAPI.

## 2. Почему не облако и не «просто Qwen в чате»

| Подход | Вердикт |
| --- | --- |
| Microsoft Copilot / Graph | Письма уходят во внешний сервис |
| OpenAI / Anthropic / любой HTTP API | Прямой выход в интернет |
| Ollama «из коробки» | Тянет модели и шлёт телеметрию |
| New Outlook | Веб-клиент, нет нормального MAPI |
| Чтение OST сторонним парсером в обход Outlook | Ломается при смене формата, юридически серая зона, плохая поддержка тредов |
| Thunderbird + IMAP | Не Outlook; IMAP на LAN допустим только если отказ от Outlook осознанный |

Рабочий контур: **Classic Outlook + Cached Exchange Mode + Extended MAPI + llama.cpp**.

## 3. Компоненты

### 3.1. Outlook Host (UI)

- Надстройка **VSTO / COM** в классическом Outlook (x64).
- Боковая панель: очередь, метки, три черновика, кнопки «В черновики» / «Перегенерировать» / «Не отвечать».
- Подписка на `NewMailEx`, смену папки, открытие письма.
- Сама надстройка **не вызывает LLM**. Только IPC на `127.0.0.1` или named pipe.

Почему не Outlook Object Model для чтения тел писем: OOM Guard показывает предупреждения, ломает автозапуск, нестабилен в STA. Чтение и запись — в sidecar на **Extended MAPI**.

### 3.2. Native MAPI Sidecar

Отдельный `MailVault.Mapi.exe` (C++/C# с Extended MAPI):

- читает EntryID, ConversationIndex, интернет-заголовки, тело (plain + HTML→text), вложения-имена, категории;
- пишет категории Outlook и объект в «Черновики»;
- стримит JSONL в orchestrator;
- не держит сеть, не логирует тела на сетевые шары.

Идемпотентность: ключ сообщения = `StoreID + EntryID` (и дубль по `InternetMessageId`, если есть).

Коммерческая альтернатива sidecar: библиотека **Redemption** (обёртка MAPI без OOM Guard). Для максимального контроля — свой sidecar.

### 3.3. Orchestrator

Локальный сервис (Go или Python 3.12 + Pydantic). Слушает только named pipe / `127.0.0.1`.

Отвечает за:

1. Очередь задач (ingest → embed → classify → draft).
2. Сбор контекста треда и RAG.
3. Валидацию JSON модели по схеме.
4. Повторы, fallback на меньшую модель, карантин битых писем.
5. Журнал аудита без отправки наружу.

Состояние: SQLite. Никакого Redis, Docker Hub, pip-install в рантайме.

### 3.4. Inference Plane

Два (лучше три) процесса `llama-server`, все `--host 127.0.0.1`:

| Процесс | Модель | Назначение |
| --- | --- | --- |
| `:8081` | Qwen3-8B Instruct Q5_K_M | Сортировка, теги, «нужен ли ответ», извлечение фактов |
| `:8082` | Qwen3.5-27B или Qwen3-32B Q5_K_M | Черновики, саммари треда |
| `:8083` | BGE-M3 / Qwen3-Embedding | Векторы для поиска по истории |

Constrained decoding: GBNF-грамматики в `schemas/`. Модель не может вернуть «простыню», только валидный JSON.

Thinking-режим Qwen — **только** для сложных писем (юридические, многосторонние треды, низкая уверенность классификатора). Для сортировки 200 писем thinking выключен: иначе очередь встанет.

### 3.5. Memory / RAG

На 200 писем в день плюс история переписки:

- **Лексика:** SQLite FTS5 по теме, телу, отправителю.
- **Семантика:** sqlite-vec, чанки ~400–800 токенов.
- **Стиль:** исходящие за 90 дней (Sent Items) — 8–15 эталонов в промпт.
- **Карточка контакта:** локальный профиль «кто это, на каком языке отвечаем, табу».
- **Тред:** все сообщения с тем же `ConversationId` / общим префиксом `ConversationIndex`.

Письмо ≠ чат. Тема «Re: договор» часто врёт. Канон — MAPI ConversationIndex.

## 4. Поток данных одного письма

```
NewMailEx
  → sidecar читает MIME/MAPI (retry 3×)
  → checksum тела, запись messages (status=ingested)
  → embedder (батч)
  → classifier GBNF JSON → categories + needs_reply + priority
  → если needs_reply:
        load thread (полный)
        retrieve: top-k похожих исходящих + факты по контакту
        drafter → 3 варианта + citations[] на EntryID
        schema validate; иначе 1 retry; иначе fallback 8B + флаг «проверьте вручную»
  → UI: карточка в панели
  → пользователь правит → sidecar создаёт Draft
  → audit: кто утвердил, хеш текста, время
```

Автоотправки нет. Нет кнопки «отправить все 40 черновиков».

## 5. Надёжность (это не «просто LLM»)

Надёжность здесь — **конвейер с детерминированными воротами**, а не «умный чат».

1. **Человек в контуре.** Модель предлагает, Outlook отправляет.
2. **GBNF + JSON Schema.** Любой ответ вне схемы — брак, не письмо.
3. **Цитаты.** Каждый факт в черновике должен ссылаться на EntryID из треда или RAG. Нет ссылки — блокер в UI («модель додумала»).
4. **Детерминированные правила раньше LLM.** VIP-отправители, домены, ключевые слова «счёт / суд / GDPR», письма от босса — правила в SQLite, не промпт.
5. **Идемпотентный ingest.** Повтор NewMailEx не плодит дубли.
6. **Очередь at-least-once** с `processing_token` и TTL. Упал процесс — задача подхватывается.
7. **Watchdog Outlook.** Outlook убивает add-in. Sidecar переживает рестарт Outlook, дочитывает checkpoint.
8. **Контрольные суммы моделей.** GGUF сверяется с манифестом при старте. Подмена файла — отказ старта.
9. **Карантин.** Письмо с битым HTML, encrypted S/MIME без ключа, огромным вложением — в `quarantine`, не в генератор.
10. **Офлайн-оценка.** Набор из 50–100 анонимизированных писем пользователя, метрики: точность класса, галлюцинации обязательств, совпадение тона. Релиз модели только если набор зелёный.
11. **Температура.** Классификатор T=0. Черновик T=0.3–0.5. Без sampling-лотереи на сортировке.
12. **Секреты.** Пароли почты система не видит. Учётные данные остаются в профиле Outlook.

S/MIME и IRM: если тело недоступно MAPI, система помечает «зашифровано, откройте в Outlook» и не выдумывает содержание.

## 6. Контекст «всей переписки»

«Вся переписка» в один промпт 200 писем не влезает и не нужна. Собирается **иерархия**:

1. Текущий тред целиком (обычно 2–30 писем) — всегда.
2. Последние N писем с тем же отправителем вне треда — если тред короткий.
3. Top-k семантически похожих исходящих ответов пользователя.
4. Карточка контакта и организации.
5. Явные факты, извлечённые классификатором (даты, суммы, номера договоров) и перепроверенные regex/парсером.

Окно модели 32k–128k достаточно. Llama 4 Scout с 10M контекста для почты избыточен и тяжёл (~55 ГБ). Не брать ради маркетинга контекста.

## 7. Сортировка

Два слоя:

**Слой A — правила (мгновенно, 100% воспроизводимо)**

- отправитель в VIP / blacklist;
- категория уже стояла в Outlook;
- тема совпала с пользовательским правилом;
- это NDR, календарный invite, рассылка по List-Unsubscribe.

**Слой B — модель 8B**

JSON: `priority`, `needs_reply`, `intent`, `language`, `suggested_folder`, `deadline_hint`, `entities`.

Результат пишется:

- в таблицу `classifications`;
- в категории Outlook (цветные метки) — пользователь видит сортировку даже без панели.

При 200 письмах слой A снимает рассылки и автоответы (часто 20–40%). Слой B обрабатывает остальное пачкой.

## 8. Генерация ответа

Промпт черновика всегда содержит:

- системная роль: «ты помощник, пишешь от имени пользователя, не выдумываешь обязательств»;
- профиль тона (из Sent Items);
- тред;
- извлечённые факты;
- запреты (не обещать сроки, которых нет в треде).

Выход — три варианта:

1. Короткий формальный.
2. Развёрнутый по пунктам.
3. Уточняющие вопросы, если данных мало.

Каждый вариант: `subject`, `body_text`, `citations[]`, `risks[]` (например «в треде нет суммы»).

HTML-письма: генерируем **plain text** (или простой HTML без внешних картинок). Внешние URL в подписи пользователя копируются из шаблона Outlook, модель их не «рисует».

## 9. Развёртывание на ПК

Офлайн-инсталлятор (ISO/USB):

- Classic Outlook уже установлен корпоративным образом.
- MailVault MSI: sidecar, orchestrator, llama-server, модели GGUF, грамматики.
- Скрипт WFP (см. `configs/wfp-airgap.ps1`).
- Проверка: попытка `llama-server` открыть внешний TCP должна быть отказана файрволом.

Обновления моделей — только файл с флешки и сверка SHA-256. Автообновлений нет.

## 10. Что сознательно отвергнуто

- **Docker + GPU на рабочей станции** — лишняя поверхность, образы тянут сеть.
- **vLLM** — серверный стек, сложнее air-gap на одном ПК.
- **Полный fine-tune 27B на исходящих** — дорого и опасно (утечка в веса). Сначала RAG + few-shot; LoRA 8B — только если стиль критичен и есть ML-инженер.
- **Автоответчик SMTP** — не соответствует требованию надёжности.
- **Чтение почты через Graph с «локальным» кэшем токена** — токен всё равно ходит в облако.

## 11. Соответствие «очень надёжный механизм»

Надёжность = (локальные данные) × (детерминированные ворота) × (человек отправляет) × (нет сети у LLM).

Модель может ошибиться в тоне. Она не должна:

- отправить письмо;
- выйти в интернет;
- выдумать номер договора без цитаты;
- потерять письмо при рестарте Outlook (очередь на диске);
- перепутать треды по теме «Re:».

Это и есть целевой уровень, а не «чтобы Qwen был умнее GPT».
