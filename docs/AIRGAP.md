# Воздушный зазор MailVault

Требование: у решения **не должно быть возможности выхода в интернет**. Outlook при этом может ходить на Exchange/M365 — это отдельный процесс с отдельной политикой.

## 1. Два контура

| Контур | Процессы | Сеть |
| --- | --- | --- |
| Почтовый | `OUTLOOK.EXE`, `OUTLOOK.EXE` add-in host | Как решит ИБ: LAN Exchange или M365. MailVault это не открывает |
| ИИ | `MailVault.Orchestrator.exe`, `llama-server.exe`, `MailVault.Mapi.exe`, embedder | Только loopback и named pipes. Любой другой IP/порт — DROP |

MAPI sidecar не открывает сокеты вообще: stdin/stdout JSONL или named pipe `\\.\pipe\mailvault-mapi`.

## 2. Почему Ollama, LM Studio, Copilot нельзя

- Ollama по умолчанию ходит за моделями и обновлениями.
- LM Studio — GUI с каталогом моделей в сети.
- Copilot / Graph — письмо покидает контур.
- pip/npm в рантайме — скрытый канал.

Инференс: статически собранный **llama.cpp / llama-server**, модели лежат в `C:\ProgramData\MailVault\models\` и проверяются по SHA-256.

Сборка llama.cpp: без `LLAMA_CURL` / без поддержки `-hf` скачивания с Hugging Face. Флаг `--host 127.0.0.1 --port ...`. Не `0.0.0.0`.

## 3. Windows Filtering Platform

Шаблон: `configs/wfp-airgap.ps1`.

Идея:

- разрешить ИИ-процессам TCP/UDP только к `127.0.0.1` и `::1`;
- запретить им всё остальное (включая DNS к 8.8.8.8, DoH, IPv6);
- не трогать `OUTLOOK.EXE` этим скриптом (иначе сломаете доставку почты).

Дополнительно:

- правило «запрет исходящих» на `python.exe` / `uv.exe` из каталога MailVault, если orchestrator на Python;
- AppLocker/WDAC: запускать только подписанные бинарники из `C:\Program Files\MailVault`.

Проверка после установки (офлайн-тест):

1. Временно подменить в тестовой сборке URL на `http://example.com` — вызов должен упасть на connect.
2. `netstat` по llama-server: слушает только 127.0.0.1.
3. Wireshark/pktmon на NIC: от ИИ-PID нет пакетов.

## 4. Данные, которые не должны уехать

- тела писем, вложения, эмбеддинги, SQLite, логи промптов;
- GGUF (это не секрет, но и не канал утечки почты).

Запрещено:

- UNC-пути `\\fileserver\...` для БД;
- OneDrive-папка профиля как путь SQLite;
- краш-репорты в Microsoft/Sentry/OpenTelemetry SaaS.

Логи: локальный файл, ротация, опционально шифрование DPAPI. Тела писем в лог **не пишем** (только EntryID, хеш, длина).

## 5. Exchange vs полный офлайн

| Сценарий | Почта приходит | ИИ работает |
| --- | --- | --- |
| Cached Exchange, есть корпоративная сеть | Да, через Outlook | Да, без интернета у ИИ |
| Самолёт, OST уже заполнен | Новые не качаются | Да, по уже скачанным |
| PST-архив, сети нет | Только архив | Да |
| New Outlook + облачный кэш | Не использовать | — |

Если политика «машина без NIC»: Outlook тоже офлайн, система работает по OST/PST.

## 6. Поставка артефактов

Первичная загрузка моделей — **вне контура** (стенд с интернетом или вендор). На рабочее место:

- USB/ISO с GGUF + SHA-256 + подпись манифеста;
- инсталлятор без `Invoke-WebRequest`.

Пользователь не должен иметь кнопки «скачать модель».
