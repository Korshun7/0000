# Пайплайн на ~200 писем в сутки

200 входящих — это не высоконагруженный кластер. Проектируем **очередь с приоритетами**, а не распределённый стрим.

## 1. Бюджет времени (ориентир, GPU 24 ГБ)

| Этап | Объём | Время |
| --- | --- | --- |
| MAPI ingest | 200 писем | 1–3 мин |
| Эмбеддинги BGE-M3 | 200 писем | < 1 мин GPU / 5–10 мин CPU |
| Классификация 8B, T=0, JSON | 200 | 3–8 мин (батчи) |
| Черновики 27B | ~30–60 писем с `needs_reply` | 10–30 мин ночью или по мере открытия |
| Онлайн на открытом письме | 1 тред | классификация < 3 с; черновик 10–40 с |

Утро: overnight-джоб уже разметил ночной поток. Днём — инкремент по NewMailEx.

## 2. Приоритеты очереди

1. Письмо, которое пользователь открыл прямо сейчас.
2. VIP / rule_hit high.
3. `needs_reply=true` за последний час.
4. Остальная классификация.
5. Backfill истории (Sent Items, старые треды) — idle.

Черновик для рассылки (`intent=newsletter`) не строится.

## 3. Сборка контекста

```
thread_messages = all with same conversation_id
                OR ConversationIndex prefix match
cap = 32 последних писем треда (если вдруг длиннее — саммари старой части 8B)

rag_sent = vector search in is_sent=1, k=8, same from_addr boost
contact  = contacts row
facts    = classifications.entities + regex dates/money
```

Промпт drafter ограничен: тред + факты + 8 исходящих. Не «вся база в контексте».

## 4. Обработка всплеска

Если за час пришло 200 писем (рассылка, инцидент):

- слой правил сразу снимает newsletter/NDR;
- классификатор батчит по 8–16;
- черновики только для `priority >= 70` или открытых писем;
- остальные ждут, UI показывает «в очереди N».

Это сохраняет интерактивность.

## 5. Сбои

| Сбой | Поведение |
| --- | --- |
| Outlook закрыт | Sidecar ждёт; очередь жива |
| Outlook перезапущен | Add-in reconnect named pipe |
| llama-server OOM | Watchdog рестарт; jobs не ACK |
| JSON не прошёл схему | 1 retry с «исправь JSON»; затем fallback 8B + флаг |
| Письмо encrypted | quarantine |
| Дубль NewMailEx | UNIQUE entry_id |

## 6. Метрики локально (без SaaS)

- `jobs` stuck > 15 мин
- доля quarantine
- доля fallback
- latency draft p50/p95
- сколько черновиков пользователь правит > 30% текста (сигнал, что модель слабая)

Дашборд — локальный HTML на 127.0.0.1 или счётчики в панели Outlook. Наружу не уезжает.
